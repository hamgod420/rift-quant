# Static Game Data & Solo-Queue Data Infrastructure

Research date: 2026-08-21. All URLs accessed 2026-08-21 unless noted. Confidence tags: **High** (verified via primary source / direct fetch, or corroborated by 2+ independent sources), **Med** (single credible source, or inferred), **Low** (weak/indirect evidence, flagged for follow-up).

---

## 1. Executive Summary

- **Data Dragon is alive and un-deprecated in 2026** (latest CDN version `16.16.1` as of 2026-08-21), still manually updated a few hours-to-days after each patch, still the right primary source for champion/item/rune base data. **High**
- **Critical gotcha: patch-name mapping changed twice in 2025 and no longer equals the CDN version string.** Marketing patch `26.16` (live since Aug 12, 2026) = Data Dragon/client version `16.16.1`. Rule: marketing `YY.NN` = client `(YY-10).NN.x`. This must be a coded lookup, not an assumption. **High**
- **Community Dragon's "convenience" JSON is materially better than Data Dragon for ability math**: it exposes per-rank numeric coefficients (cost/cooldown/scaling/effect amounts); Data Dragon only gives tooltip `effect`/`effectBurn` strings that are documented as sometimes inaccurate. Use CDragon for anything that needs real ability scaling. **High**
- **No maintained official or third-party "champion X buffed/nerfed on patch Y" structured feed exists.** The one community project built for this (`CommunityDragon/LeaguePatchNotes`) is dead (stalled at 2018 patches). A newer volunteer repo (`WordlessMeteor/LoL-Patch-Change`) mirrors raw DDragon/CDragon diffs per patch and is current through Aug 2026, but it's a single-maintainer bus-factor risk. **High** (dead project) / **Med** (viability of the alternative)
- **The most robust patch-diff approach is to build it yourself**: every historical Data Dragon version stays live at its own CDN path, so you can snapshot+diff `champion.json`/CDragon's per-champion JSON across consecutive patches without depending on any third party. **High**
- **Riot API key tiers, confirmed on the current portal**: Development (20 req/1s, 100 req/2min, expires every 24h) → Personal (same limits, but persistent, no approval needed, no public distribution) → Production (starts at 500 req/10s + 30,000 req/10min, requires an app review, ~10 business days nominal but real cases pending 6+ weeks in 2025). **High**
- **A Personal key is almost certainly sufficient for the pro-soloq-tracking use case** — sustained ceiling is ~50 req/min (~72k req/day theoretical), vastly more than needed to poll a few hundred pro accounts daily. Production key only matters if you also want to mass-scrape the general ranked ladder yourself. **High** (math), **Med** (sizing assumption)
- **2025-2026 Riot API policy change: Spectator-V5 (live/current-game-info) is being deactivated** as part of new in-client anonymity features; Riot explicitly confirmed Match-V5 and leaderboards are unaffected. Riot's public "API Change Log" page is stale since 2018 — don't trust it, watch `@RiotGamesDevRel` / developer-relations GitHub instead. **High**
- **Match-v5 historical data retention is ~2 years, with at least one reported case of data being purged after only 1 year.** Plan for continuous ingestion starting now, not a deep future backfill. **Med-High**
- **China's LPL "Super Server" solo queue is not reachable through Riot's official API at all** — it's Tencent-operated infrastructure, completely separate from Riot's global backend. No third-party tracker found in this pass covers it either. This is a real coverage gap for LPL player-form signal. **High**
- **dpm.lol, trackingthepros.com, and deeplol.gg all have scrape-tolerant `robots.txt` (some explicitly allow AI/LLM crawlers) but none publish a documented public API.** `lolpros.gg` is the best-documented methodology (multi-account tracking, PUUID-anchored, refreshed every 6h) via its own FAQ, though it also lacks a first-party API. **Med-High**
- **op.gg has a real robots.txt-vs-Terms-of-Service contradiction**: robots.txt is largely permissive, but the ToS explicitly bans "automated scripts," "scraping," and "data mining." Treat op.gg as legally off-limits for automated collection despite the permissive robots.txt. **High**
- **No official winrate/pickrate-by-patch API exists from lolalytics, u.gg, or op.gg.** lolalytics/u.gg use the newer IETF Content-Signal robots directive (`ai-train=no, use=reference`) which is ambiguous for a research pipeline (not a clear green light). For **pro-play** meta by patch, Oracle's Elixir (free, bulk, explicitly built for analysts) and gol.gg (patch-segmented tournament stats) are the best fits; GRID is Riot's official exclusive esports data partner but is sales-gated, not self-serve for a hobby/research project. **High**

## 2. Detailed Findings

### 2.1 Data Dragon

- Base URL `ddragon.leagueoflegends.com`. Serves champion base stats/abilities/tags (`champion.json`, `champion/{id}.json`), items (`item.json`), runes (`runesReforged.json`), summoner spells, profile icons, and per-region client version via `realms/{region}.json` (e.g. `na.json`). [Data Dragon docs – Riot Developer Portal](https://developer.riotgames.com/docs/lol) (2026-08-21). **High**
- Update process is **manual** — Riot Games Developer Relations documentation states Data Dragon updates are done by hand after each patch and are "not always updated immediately." [Riot API Libraries – Data Dragon](https://riot-api-libraries.readthedocs.io/en/latest/ddragon.html) (2026-08-21). **High**
- Confirmed live via direct fetch of `https://ddragon.leagueoflegends.com/api/versions.json` on 2026-08-21: newest entries `16.16.1, 16.15.1, 16.14.1, ... 15.24.1, 15.23.1, ...`, ~400 total entries going back to `0.x` versions, mixing numbered versions and `lolpatch_x.x` tags for the very oldest patches. **High**
- Historical gaps exist for the oldest hotfix patches (e.g. some 3.6.x hotfixes were never packaged into ddragon), per community `OLDPATCHS.md` trackers, but this is irrelevant for a project scoped to 2025-2026 data. [noxelisdev/LoL_DDragon](https://github.com/noxelisdev/LoL_DDragon) (2026-08-21). **Med**
- Ability numeric data is tooltip-shaped, not calculation-shaped: `effect` (array per level), `effectBurn` (string of all values), and `vars` resolve `{{ aN }}`/`{{ fN }}` placeholders in tooltip text — and this data is explicitly documented as sometimes **inaccurate**, especially for spells. [Hextechdocs – Resolving spells and variables in spell texts](https://hextechdocs.dev/resolving-variables-in-spell-textsa/) (2026-08-21). **Med-High**
- No deprecation announcement found anywhere (official changelog, GitHub, dev relations). It remains the sole official "static data" source since `lol-static-data-v3` was deprecated years ago in its favor. **High** (absence of deprecation signal, checked directly)

**Patch-name-to-version mapping (load-bearing finding):**
- Through 2024, marketing patch name and client version were identical (e.g. "Patch 14.23" = client `14.23`).
- From Jan 9, 2025, Riot renamed marketing patches to a year.split.patch scheme: `V25.S1.1` = client `15.1`. [League of Legends Wiki – V25.S1.1](https://wiki.leagueoflegends.com/en-us/V25.S1.1) (2026-08-21). **High**
- Within the first split (around the 4th patch, released Feb 20, 2025), Riot switched again to a flat sequential scheme: `Patch 25.04` = client `15.4`. [League of Legends Wiki – V25.04](https://wiki.leagueoflegends.com/en-us/V25.04); [Sportskeeda](https://www.sportskeeda.com/esports/league-legends-patch-25-04-notes-ashe-buffs-kalista-nerfs) (2026-08-21). **High**
- Current state confirmed 2026-08-21: marketing "Patch 26.16" has been live since Aug 12, 2026 [dotesports – LoL Patch 26.16 notes](https://dotesports.com/league-of-legends/guides/lol-patch-26-16-notes) (2026-08-21), while Data Dragon's newest version is `16.16.1` (fetched directly). This confirms the client version silently kept incrementing on the old "(year-2010).patch" scheme even while the public-facing marketing name changed format twice.
- **Rule to implement**: `marketing_patch("YY.NN") == client_version("{YY-10}.NN.x")`. Any join between `match.info.gameVersion` (client scheme), Data Dragon/CDragon paths (client scheme), and public patch notes / balance-change narratives (marketing scheme) needs this translation. Write it as a tested utility, since Riot has already changed the marketing-facing format twice within 18 months — don't assume it's stable going forward.

### 2.2 Community Dragon

- Community-run (not Riot-operated), covered by Riot's general "Legal Jibber Jabber" fan-content policy; site footer explicitly states "Riot Games does not endorse or sponsor this project." [communitydragon.org footer, fetched 2026-08-21]. **High**
- Two tiers of access: raw scraped game/LCU files at `raw.communitydragon.org` (root = LCU files, `game/` = client files, `game/data/characters/{champ}/{champ}.bin.json` = deepest mechanics data but "no unified format," hard to parse) and curated **convenience JSON** at `raw.communitydragon.org/latest/plugins/rcp-be-lol-game-data/global/default/v1/...`. [CommunityDragon/Docs – assets.md](https://github.com/CommunityDragon/Docs/blob/master/assets.md) (2026-08-21). **High**
- **Verified directly** (fetched `.../v1/champions/1.json`, Annie, 2026-08-21): the convenience JSON contains genuinely structured ability math — `range` arrays per rank, `costCoefficients`, `cooldownCoefficients`, scaling `coefficients` (AP/AD ratios), `effectAmounts` (10 slots, per-rank), ammo/recharge mechanics — "far exceeds tooltip strings... enabling precise game calculations." This is the single clearest differentiator vs. Data Dragon for anyone encoding true champion ability strength. **High**
- Path-based versioning (`latest/`, `pbe/`, and explicit patch numbers, e.g. `8.23/` referenced in docs) — supports historical pulls, though exact retention window isn't documented. Docs warn "files are sometimes reorganized by Riot," meaning CDragon's own path structure has shifted over the years and could again. **Med**
- Stability for programmatic use: no `robots.txt` restriction found (request returned the site's generic 404 page, i.e., no robots.txt exists — effectively unrestricted); backed by Discord + Patreon + an active GitHub org (`communitydragon/*`), used broadly across the LoL dev ecosystem for years. No SLA since it's volunteer-run. **Med-High**

### 2.3 Structured per-patch balance-change data

- **`CommunityDragon/LeaguePatchNotes`** (parses official patch-notes text into JSON): confirmed dead — only supports patches **8.13 to 8.22** (2018). Not usable. [GitHub](https://github.com/CommunityDragon/LeaguePatchNotes) (2026-08-21). **High**
- **`WordlessMeteor/LoL-Patch-Change`**: a Chinese-authored, actively updated repo storing per-patch JSON diffs sourced from both CDragon and Data Dragon, covering champions/items/game assets, in both `default` (English) and `zh_CN` locales, tracking both `Latest` and `PBE`. Verified via direct fetch: log entries through **2026-08-21** (today). Full historical diffs are archived separately (~30GB) to keep the main repo small. It gives raw before/after data-file diffs rather than human-authored "buffed/nerfed" labels — which is actually fine (better, even) for ML feature engineering, since you get exact numeric deltas. [GitHub – WordlessMeteor/LoL-Patch-Change](https://github.com/WordlessMeteor/LoL-Patch-Change) (2026-08-21). **Med** (single-maintainer risk; re-verify liveness periodically before depending on it)
- **DIY diffing is fully viable and lowest-risk**: because every historical Data Dragon version remains addressable by its own version string (confirmed via the versions.json fetch above), and CDragon similarly supports patch-specific paths, you can snapshot the champion/item JSON at consecutive patches yourself and compute diffs — no dependency on a volunteer project at all. **High**
- For the *qualitative* "why" behind a change (design intent, not just the number), there is no API — only the official patch notes text (`leagueoflegends.com/en-us/news/tags/patch-notes/`) or the wiki, which would need HTML scraping / LLM extraction. [leagueoflegends.com patch notes tag](https://www.leagueoflegends.com/en-us/news/tags/patch-notes/) (2026-08-21). **High**
- Commercial alternative: **PandaScore** offers a paid esports API that versions LoL static resources (champions/items/spells/runes) alongside match/replay data, letting you compare champion data across patch versions natively. Pricing not retrieved in this pass. [PandaScore – League of Legends docs](https://developers.pandascore.co/docs/league-of-legends) (2026-08-21). **Med** (existence/feature set), **Low** (cost — needs follow-up)

### 2.4 Riot API for solo queue (match-v5 / league-v4)

**Key tiers** (current Developer Portal, confirmed across two independent docs):

| Key type | Rate limit | Expiry | Requirements |
|---|---|---|---|
| Development | 20 req/1s, 100 req/2min | 24 hours (must regenerate) | None — instant |
| Personal | 20 req/1s, 100 req/2min (same as dev) | Persistent | None — instant; no public distribution, no rate-limit increases |
| Production | Starts 500 req/10s, 30,000 req/10min; expandable | Persistent | Application review (~10 business days nominal; real 2025 case pending 6+ weeks), requires a working prototype/site |

Sources: [Riot Developer Portal – Rate Limiting](https://developer.riotgames.com/docs/portal) (2026-08-21, direct fetch), [Riot API Libraries – Your Application](https://riot-api-libraries.readthedocs.io/en/latest/applications.html) (2026-08-21, direct fetch), [GitHub issue – 6+ week pending production key, 2025](https://github.com/RiotGames/developer-relations/issues/1099) (2026-08-21). **High**

- Method-level defaults (from Hextechdocs, generally consistent with the above): match endpoints 500 req/10s, league endpoints (GLOBAL) 500 req/10s, champion 400 req/1min, summoner 600-2,000 req/1min depending on region, tournament-stub 10 req/10s. Riot explicitly warns not to hardcode these — read the `X-App-Rate-Limit`/`X-Method-Rate-Limit` response headers at runtime. [Hextechdocs – Rate Limiting](https://hextechdocs.dev/rate-limiting/) (2026-08-21). **High**
- **Throughput sizing**: Personal/Dev key's binding constraint is 100 req/2min = 50 req/min sustained ≈ 72,000 req/day theoretical (24/7, zero margin). One request ≈ one match pulled (match-v5 by ID) or one page of up to 100 match IDs (by PUUID). Tracking a few hundred pro accounts for new games + rank once or more per day consumes a tiny fraction of this budget — **a Personal key is sufficient for the core pro-soloq use case**; Production is only needed if you separately decide to mass-crawl the general ladder for meta-strength priors yourself (see 2.6). **High** (arithmetic), **Med** (whether your eventual design needs ladder-wide scraping)
- **2025-2026 policy change**: Riot Games Developer Relations announced (X/Twitter, 2025) that **Spectator-V5 is being deactivated** in coordination with new in-client LoL "anonymity" features, specifically to stop third-party apps from de-anonymizing players in live games. Riot explicitly stated **post-match APIs like Match-V5 and leaderboards are unaffected**. [@RiotGamesDevRel](https://x.com/RiotGamesDevRel/status/1979263978787246391) (2026-08-21). **High**
- Riot's public **"API Change Log"** page is stale — last entry dated October 2018, nothing about 2025/2026 changes (confirmed via direct fetch). Treat it as unreliable; monitor `support-developer.riotgames.com`, the `RiotGames/developer-relations` GitHub repo's issues, and `@RiotGamesDevRel` instead. [Riot Games API Change Log](https://www.riotgames.com/en/DevRel/riot-games-api-change-log) (2026-08-21, direct fetch). **High**
- **Match data retention**: officially ~2 years. A GitHub bug report describes match-v5 data being deleted after only 1 year in some cases instead of 2. [GitHub issue #902](https://github.com/RiotGames/developer-relations/issues/902) (2026-08-21). Plan the pipeline around continuous/near-real-time ingestion rather than assuming a multi-year backfill will always be possible later. **Med-High**
- **API Terms relevant to rift-quant** (direct fetch of `developer.riotgames.com/terms`, 2026-08-21): redistribution of raw Game Information is prohibited; you must delete all Game Information on key termination; you may not use the API to "collect any additional information... not provided" or build anything that "violate[s] anyone's privacy rights"; commercial use (e.g., ever monetizing a win-probability product) requires separate written Riot approval. **High**
- **China coverage gap**: Tencent-operated China realms are not reachable via Riot's global developer API — confirmed via multiple sources; this is a structural/infrastructure separation, not a ToS restriction. Riot's API has separately been rolling out (beta) to Garena-operated SEA servers, which is a different situation from China. [search corroboration, 2026-08-21]. **High**

### 2.5 Pro player → solo queue account mapping

- **dpm.lol**: has a dedicated "Pro SoloQ Tracker" and "Solo Queue Team Ranking" covering LEC/LCK/LPL and more (`dpm.lol/esport/soloq/{league}`). [DPM.LOL](https://dpm.lol/esport/soloq/lck) (2026-08-21). No documented public API. `robots.txt` (fetched 2026-08-21) explicitly **allows** AI/LLM crawlers (`ClaudeBot`, `GPTBot`, `ChatGPT-User`, `PerplexityBot`, `Google-Extended` all set `Allow: /`), blocks only `/privacy`, `/tos`, `/legal`, and one specific path (`/v1/players/*/champions/versus-by-lane`) for Googlebot — the disallowed path's `/v1/...` shape implies an internal versioned JSON API backs the site, though nothing is publicly documented. **Med** (site behavior/tolerance), **Low** (existence of a usable API — inferred, not confirmed)
- **trackingthepros.com**: lists all pro players ranked by soloq rank, plus a personalized "My Pro Tracker" and win-prediction feature. `robots.txt` is fully open (`User-agent: * / Disallow:` — nothing blocked). No documented public API found. [trackingthepros.com](https://www.trackingthepros.com/players) (2026-08-21). **Med**
- **deeplol.gg**: LoL stats/AI-score site with pro-comparison "AI-Score" features. Both `deeplol.gg` and `m.deeplol.gg` robots.txt are fully open (`Allow: /`). No documented public API found. **Med**
- **lolpros.gg**: no first-party public developer API, but its own FAQ documents its methodology clearly — it tracks **multiple ranked accounts per pro** (a `primaryAccount` plus others), refreshed **4 times a day, every 6 hours starting at midnight CET**, with country/region and role metadata. A third-party wrapper (Parse.bot) exposes this as a semi-structured API. This is the best-documented account-mapping methodology found in this pass. [LOLPros.GG FAQ](https://lolpros.gg/about/faq) (2026-08-21). **Med-High**
- **Riot ID renames**: none of the trackers above publish an explicit rename-handling policy, but the underlying fact that makes this tractable is well-established: a Riot account's **PUUID is stable across Riot ID name/tag changes** (and even historically across the 2023 summoner-name→Riot-ID migration), while the display name is not. A niche tool, `lols.gg`, markets exactly this — a name-change history keyed to PUUID. **Recommendation: use PUUID as the durable internal join key** for pro players, seeded once from any of the above trackers, and re-resolve display names opportunistically rather than keying on name#tag. **High** (PUUID stability is a well-documented Riot API property)
- **Chinese (LPL) solo queue coverage**: no tracker in this pass was confirmed to cover Tencent's China Super Server (consistent with 2.4's finding that Riot's API can't reach it — these trackers are Riot-API-based). One search surfaced that LPL pros are contractually required to keep an active Super Server account (min. 24 games/month) but "most LPL pros openly prefer the Korean server for actual practice" — meaning even a China-side data source might undersample real practice activity relative to KR. **Open question / gap**, flagged in Section 4. **Med**

### 2.6 Meta statistics sources (lolalytics / u.gg / op.gg / pro-play aggregators)

- **No official public data-download or REST API** exists from lolalytics, u.gg, or op.gg for champion winrate/pickrate-by-patch-and-rank. Only unofficial community wrappers were found (a Parse.bot lolalytics wrapper; a `Zadag/simple-u.gg-api` GitHub scraper). OP.GG does run an **MCP server** (`mcp-api.op.gg/mcp`) but it's designed for AI-agent tool-use / live lookups, not bulk historical export. **High**
- **op.gg — direct contradiction found between robots.txt and Terms of Use.** `robots.txt` (fetched 2026-08-21) is largely permissive for generic user-agents (`User-agent: * / Allow: /`, only blocking a couple of query-string patterns and one bot literally named `carbon-umbrella-bot`). But the **Terms of Use** (fetched directly, `op.gg/lol/policies/agreement`, 2026-08-21) explicitly prohibits: automated scripts to collect information, "scraping or data mining," actions that could overload their infrastructure, and content copying/modification. **Recommendation: do not build an automated op.gg scraper without explicit legal sign-off; robots.txt permissiveness does not override the ToS prohibition.** **High**
- **lolalytics.com and u.gg** use the newer IETF **Content-Signal** robots directive: `User-agent: * → Content-Signal: search=yes, ai-train=no, use=reference; Allow: /`, plus explicit full `Disallow: /` for known AI-training crawlers (`Amazonbot`, `Applebot-Extended`, `Bytespider`). This is narrower than op.gg's outright ToS ban, but it's not a green light either — `ai-train=no` clearly forbids training generative models on the content, and `use=reference` is ambiguous for a quantitative feature-extraction pipeline. Full ToS text for these two sites was **not** retrieved in this pass (should be checked before building anything). **Med** (robots.txt read directly) / **Low** (full ToS terms — open item)
- Neither lolalytics, u.gg, nor op.gg appears to publish a **pro-play-only** cut of their tier lists — all three are ranked-ladder-based (all-rank or high-elo aggregates). **Med-High**
- **Best fits for pro-play meta-by-patch specifically:**
  - **Oracle's Elixir**: free, bulk, explicitly-for-analysts downloadable datasets (XLSX) of official Riot competitive games from **2016 to present**, each row carrying patch/game metadata; maintained by Tim "Magic" Sevenhuysen. This is the single best-fit source for this need. [Oracle's Elixir – Match Data Downloads](https://lol.timsevenhuysen.com/matchdata/) (2026-08-21). **High**
  - **gol.gg ("Games of Legends")**: patch-segmented tournament statistics (picks/bans/winrate/KDA cut by patch and by tournament) covering LCS/LCK/LPL and more, running since 2014. `robots.txt` (fetched 2026-08-21) blocks `/meta/`, `/raw/`, `/ranking/`, `/summoner/`, `/user/`, `/league-admin/`, and a long list of known scraper/SEO bots (Ahrefs, Semrush, MJ12, dotbot, BLEXBot, etc.) by name — but does **not** block generic `User-agent: *` access to its main stats/tournament pages. Reasonable best-effort scrape target for supplementary detail; verify their ToS text before heavy automation (not retrieved in this pass). [gol.gg](https://gol.gg/esports/home/) (2026-08-21). **Med**
  - **GRID**: Riot Games' official **exclusive** worldwide esports data partner (real-time, feed-level data, equity relationship with Riot). Access is segmented and sales-gated: Pro Teams get free scrim/tournament data access; **Betting & Fantasy** and **Other** use cases require contacting sales for a custom quote. No visible self-serve free tier for an independent research project was found. Treat as a stretch-goal / future paid option, not a v1 source. [grid.gg – Get League of Legends data](https://grid.gg/get-league-of-legends/) (2026-08-21, direct fetch). **Med**
  - **probuilds.net / pros.lol / u.gg "probuilds"**: show current individual pro-player item/rune loadouts by named player, refreshed roughly every 15 minutes — useful as a champion-pool / "what is this specific pro playing right now" signal, complementary to gol.gg's aggregated stats rather than a replacement. **Med**

## 3. Concrete Recommendations

**Ingestion priority order:**

1. **Data Dragon** as the primary static-data source (champion/item/rune base stats, tags, icons) — zero auth, stable, versioned by patch. Pull and archive every version going forward; don't rely on "latest" only.
2. **Community Dragon convenience JSON** (`raw.communitydragon.org/.../v1/champions/{id}.json`) as an enrichment layer specifically for ability scaling coefficients Data Dragon doesn't expose cleanly. Cross-validate the two where they overlap (ddragon's own ability numbers are documented as sometimes wrong).
3. **Build your own patch-diff pipeline** by snapshotting Data Dragon + CDragon JSON at each new version and diffing against the prior one. Treat `WordlessMeteor/LoL-Patch-Change` as a convenience cross-check, not a hard dependency (single-maintainer risk). Don't bother with `CommunityDragon/LeaguePatchNotes` — it's dead.
4. **Riot solo-queue data**: register a **Personal API key** immediately (instant approval, persistent, no daily regen) and build the full pro-tracking pipeline against it. Its ~50 req/min sustained ceiling comfortably covers polling a few hundred pro accounts for new games and rank at least daily. Only start a **Production key** application (budget several weeks, needs a live prototype/site) if you later decide to also crawl the general ranked ladder at scale for meta priors.
5. **Seed pro-player → PUUID mapping** from `lolpros.gg` (best-documented refresh cadence: every 6h) cross-checked against `dpm.lol`'s pro soloq tracker and `trackingthepros.com`. Store **PUUID**, not Riot ID/name, as the durable join key — names and tags change, PUUID doesn't.
6. **Meta-strength priors (ranked ladder)**: avoid automating op.gg (ToS explicitly forbids scraping despite a permissive robots.txt). If lolalytics/u.gg-derived features are needed, get a lightweight legal review first given the Content-Signal ambiguity, keep volume low, cache aggressively, and attribute; alternatively look at a paid data provider (PandaScore) if this becomes a hard requirement.
7. **Pro-play meta-by-patch**: ingest Oracle's Elixir's free XLSX drops as the backbone (already patch-tagged, bulk, explicitly licensed for this kind of use) and supplement with gol.gg for finer patch/tournament detail where needed.

**Key numbers to encode in the pipeline:**

- Personal/Dev key: 20 req/1s, 100 req/2min → ~50 req/min sustained.
- Production key starting point: 500 req/10s, 30,000 req/10min (expandable case-by-case).
- Match data retention: plan for ~1-2 years rolling window, not indefinite.
- Patch-string offset: marketing `YY.NN` = client/CDN version `(YY-10).NN.x` (verified against 25.S1.1→15.1, 25.04→15.4, 26.16→16.16.1 as of 2026-08-21) — write this as a small tested utility, not a hardcoded constant, since the marketing format itself already changed twice in 2025.

## 4. Open Questions / Risks

- **China Super Server (LPL) solo queue has no identified data path.** Riot's API can't reach it, and no tracker reviewed here (dpm.lol, trackingthepros, deeplol, lolpros) was confirmed to cover it. Needs dedicated follow-up research into China-specific community tools, or an explicit decision to treat LPL player-form signal as KR/bootcamp-account-only (noting most LPL pros reportedly prefer KR soloq for real practice anyway, which may partially mitigate this).
- **op.gg is legally off-limits for scraping** per their own ToS despite a permissive-looking robots.txt — needs an explicit product decision (skip op.gg entirely vs. seek a data licensing conversation).
- **lolalytics/u.gg full Terms of Service were not reviewed** in this pass (only robots.txt) — should be checked before any automated collection is built against them, since Content-Signal alone is a copyright-reservation mechanism, not a full usage license.
- **`WordlessMeteor/LoL-Patch-Change` is a single-maintainer volunteer repo** — verify it's still active before depending on it; have the DIY-diffing fallback (Section 3, item 3) ready regardless.
